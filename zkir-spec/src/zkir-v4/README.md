# ZKIR v4 in Agda

This development models the 51 instructions of IR 4.0 at the [`zkir-4.0.0-rc.1` source pin](https://github.com/midnightntwrk/midnight-zkir/tree/3ec876c0a311e4979536ae432d2c810e324ace64).  The [language reference](../../docs/zkir-v4-spec.md) gives the wire format, two execution passes, statement layout and Rust examples.  [Main.agda](Main.agda) imports the entire v4 development.  Run the [aggregate checks](../README.md) from the toolchain directory.

## From source to statement

| Question | Definitions and results |
| --- | --- |
| Which programs and values can be represented? | [Types](Types.agda) and [Syntax](Syntax.agda) define the value and instruction constructors.  [Validation](Validation.agda) checks the proof-name store, accumulator lifecycle and fixed-key references.  [Producer](Producer.agda) checks single assignment, operand types, widths, arities and output placement and computes chip selection.  For aligned hashes it counts the native operands required by the field and byte atoms in the descriptor.  Its `range-check-configuration` theorem proves that successful inference selects one range-check group with the backend’s default lane width. |
| Which encodings does the interpreter accept? | [Encoding](Encoding.agda) defines field-list encoding and decoding.  [EncodingProperties](EncodingProperties.agda) proves the width and both directions of canonical decoding under the stated primitive laws.  [InputProperties](InputProperties.agda) extends these results to ordered declarations and memory. |
| What does a successful run establish? | [Operations](Operations.agda) defines value computations.  [Semantics](Semantics.agda) supplies input streams, proof slots, public inputs, output values and the commitment check.  [SemanticsProperties](SemanticsProperties.agda) proves determinism, exhaustion, prefix growth for each public-input block, and correspondence of the carried block and count to the program's exposures. |
| What happens to an inactive proof? | [ProofSlots](ProofSlots.agda) normalizes a list of guarded slots.  [SlotReplay](SlotReplay.agda) proves that replacing a preimage's proof list by the interpreter's normalized list reproduces the same complete final state. |
| Which constraints are checked? | [Circuit](Circuit.agda) constructs and executes a list of chip contracts.  [CircuitProperties](CircuitProperties.agda) connects a successful circuit to its public instance.  [CircuitBridge](CircuitBridge.agda), [CircuitPure](CircuitPure.agda) and [CircuitEffects](CircuitEffects.agda) compare the two passes instruction by instruction.  [CircuitDiagnostics](CircuitDiagnostics.agda) relates diagnostic-free assignments to the witnesses used for replay. |
| When does the honest witness satisfy the circuit? | [ProducerCorrespondence](ProducerCorrespondence.agda) proves `producer-forward` from producer acceptance, successful preprocessing, the forward preparation contract and the primitive conditions of the run.  [ProducerCompute](ProducerCompute.agda) proves that successful computations write exactly their inferred names and types.  [ProducerMemory](ProducerMemory.agda) uses single assignment to derive agreement with the honest witness.  [ComparisonWidths](ComparisonWidths.agda) specializes the forward theorem to RC1’s comparison-width cap. |
| Which satisfying witnesses have a preimage? | `producer-extract` constructs a preimage whose run agrees on both stores, returns and public blocks, given circuit satisfaction and the [remaining local conditions](ProducerResiduals.agda).  On the [source fragment](ReplayFragment.agda), `fragment-extract` applies to every satisfying witness.  [ReverseProducer](ReverseProducer.agda) derives stability of committed inputs during replay.  The target view retains the original circuit’s unused proof-slot suffix. |
| What do the variable-guard examples establish? | For the sources in §§7.2–7.3, `one-replay` and `fold-replay` reconstruct a VM run from every satisfying witness using backward preparation.  They preserve the public blocks, normalize inactive slots, and recover the guard and impact skips.  Under full-instance backend extraction and the codec laws, `one-sound` and `fold-sound` identify the reconstructed statement and carried accumulator with those checked by the ledger.  [Source replay](GuardedExamples.agda) · [Ledger theorems](GuardedStatementSoundness.agda) |
| What does extraction recover from an honest witness? | `producer-honest-round-trip` recovers the canonical preimage of any successful producer run under the forward preparation contract and the run’s forward primitive conditions.  [ProducerCorrespondence](ProducerCorrespondence.agda) |
| What is unique? | [StatementUniqueness](StatementUniqueness.agda) proves that two honest explanations of one witness agree after erasing inactive proof bytes and a disabled commitment. |
| How are active preparations and folds accounted for? | [Guarantees and assumptions (§5.2)](../../docs/zkir-v4-spec.md#52-preparation-folding-and-exposure) · [AccumulatorVerification](AccumulatorVerification.agda) · [AccumulatorObligations](AccumulatorObligations.agda) |
| What connects separate, folded and nested proofs? | [Wrapper guarantees (§5.3)](../../docs/zkir-v4-spec.md#53-checking-two-proofs-separately-or-together) · [RecursiveVerification](RecursiveVerification.agda) |
| How does a proof establish a sequence of transitions? | `execution-or-bad-fold` returns the execution or a path from the accepted root through its predecessors to the failed fold.  [Counter guarantees (§5.4)](../../docs/zkir-v4-spec.md#54-proving-a-sequence-of-exactly-n-transitions) · [General induction](SequentialVerification.agda) · [Counter soundness](SequentialExample.agda) · [Counter completeness](SequentialCompleteness.agda) |
| How are application proof trees verified? | [Tree guarantees (§5.5)](../../docs/zkir-v4-spec.md#55-proving-a-tree-of-application-claims) · [TreeSoundness](TreeSoundness.agda) · [TreeCompleteness](TreeCompleteness.agda) |
| How do counter segments split, join and regroup? | [Segment guarantees (§5.6)](../../docs/zkir-v4-spec.md#56-splitting-and-joining-counter-segments) · [SegmentSoundness](SegmentSoundness.agda) · [SegmentCompleteness](SegmentCompleteness.agda) · [SegmentRegroup](SegmentRegroup.agda) |
| How does verification use the statement? | [Protocol](Protocol.agda) proves the carried prefix occupies twelve fields per accumulator.  In [ProducerCorrespondence.ForKey](ProducerCorrespondence.agda), `complete-from-producer` uses backend completeness and valid exposed pairings.  For RC1, `complete-with-comparison-cap` requires every requested comparison width to be at most 252 bits and takes backend completeness for the capped checker.  `sound-on-fragment` uses ordinary extraction of a satisfying witness bound to the full instance and recovers a single VM run with the caller’s statement and the proof’s ordered list of carried accumulators. ## Trust boundary

The bad-fold reductions identify an actual ordered tuple of accumulators with a valid folded output and an invalid input.  Computational soundness requires efficient extraction and proof recovery through the relevant depth, together with a bound on producing such a tuple for the pinned fold.  The binary ideal-hash estimate and its assumptions are in the [language reference, §5.2](../../docs/zkir-v4-spec.md#52-preparation-folding-and-exposure).

[Assumptions](Assumptions.agda) supplies the field, group, hash and verifier primitives.  The development takes primitive laws as parameters and typechecks with Agda's `--safe` option.  Typed codec round trips use the additional byte and G1 codec laws in [EncodingProperties](EncodingProperties.agda).  Fixed-key preparation uses the primitive agreement in [CircuitEffects](CircuitEffects.agda).  Outer proof completeness, knowledge soundness and the pairing check concern the bound verifier parameters.  These properties of the cryptography and the gate-level Rust implementations are external to the Agda development.

[CorrespondenceExamples](CorrespondenceExamples.agda) applies both correspondence theorems to the byte-packing example in §7.1.  It also checks producer acceptance and fragment membership for a committed comparison with a private input.  [ReverseBoundaryExamples](ReverseBoundaryExamples.agda) exhibits the different values stored by the two passes for a disabled transcript read and a disabled proof slot.  [BoundaryExamples](BoundaryExamples.agda) checks field and byte bounds, guard matching, slot counts, key use and exposure order.  [WitnessExamples](WitnessExamples.agda) checks a skipped impact and guarded fixed-key preparation.  [ReferenceExample](ReferenceExample.agda) evaluates the complete 32-byte example from §7.1 and checks its typed return, public fields and skip list.  The [Rust examples](../../../zkir/src/spec_examples.rs) load the language reference through the JSON loader.
